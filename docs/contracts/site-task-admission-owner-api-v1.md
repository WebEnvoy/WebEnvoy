# Managed Site Task Owner Admission API V1

Status: Accepted for #475. Owner: Core. Request schema: [`site-task-admission-owner-operation-request.schema.json`](../../packages/schemas/schemas/site-task-admission-owner-operation-request.schema.json). Route: `POST /owner/site-task-admissions/operations`; it requires the Core supervisor Bearer credential and rejects Agent credentials.

The owner first selects an absolute, local Git repository with `select_authoring_repository`. Core requires that the selected path is the repository root, is not a symlink path, is outside the Core managed data root and managed package materialization, and is clean at selection and at each subsequent check. The repository path remains in Core owner state and is not returned by the API. Agent-facing operations never accept a path, pin, digest, task body, code receipt, or filesystem root.

`inspect_candidate` takes an opaque selected repository ref, an exact Core-approved base revision, and the package/task identity. Core derives the candidate pin from that checkout's Lode local package index and manifest; checks that the same package/task/capability is retained and its semantic version advances; verifies all package bytes, digest, schemas, declarations, lock and script metadata using the same package verifier as static pins; requires the manifest source commit to be a reachable ancestor of the clean authoring `HEAD`; checks package source-file bytes against the Git tree at that source commit; and runs `node --check` on the declared script. It reports an opaque candidate ref, source and authoring commits, changed package paths and a diff digest. `candidate_diff` returns only the exact bounded diff for owner review. It does not execute or install candidate code.

The owner explicitly calls `admit_source` for the inspected candidate. Core repeats candidate verification and rejects any change since inspection, then creates an immutable local source revision and receipt bound to its base revision, package revision/digest, source ref/commit, authoring commit and task. This receipt makes the derived package available through the existing source resolver; source admission does not install, enable, or authorize script execution.

For a declared script, the owner separately calls `admit_code` after reviewing and validating the candidate. Core rechecks the exact authoring commit and package bytes, then records the package verifier's code admission ref for the exact package/revision/digest/script hash. Without a current code receipt, the package can follow normal disabled install/enable lifecycle and be read, but script dispatch is denied. `revoke_code` preserves the source receipt while preventing new dispatches; `revoke_source` makes the source unavailable to install or new task resolution and also deactivates its code receipt. Install remains disabled by default and owner enable/rollback uses the existing skill lifecycle CAS.

Disable, rollback, and source/code revocation are prospective: they prevent new Runs from selecting or dispatching through the affected revision. A Run already created keeps its exact package, source/code admission refs, script hash, and result; query and historical reads use those persisted Run facts and do not require the currently enabled revision or an active admission receipt. In-flight callbacks use the Run's fixed verified script bytes and recheck the original Grant and Harbor ControlLease; they do not re-resolve current enablement or replay an unknown dispatch. Revocation never deletes, rewrites, or makes an existing Run's history unavailable.

The route returns refs, hashes, bounded path lists, and fixed status codes. It does not return the private repository path, package source bytes outside an explicit owner-only bounded diff request, credentials, page data, or Runtime evidence. `list_admissions` is owner-only and is not a replacement for the managed skill library's installed/enable receipts.
